# CASSIE Demo Mode

Demo mode allows public/academic users to explore CASSIE using admin-generated one-time codes, without exposing real user accounts or enabling uploads of personal/patient data.

---

## How It Works

- Public registration is disabled; only admins can log in via the normal login page
- Visitors use a one-time **demo code** (generated by an admin) to start a temporary session
- Demo sessions are time-limited (default 2 hours) and restricted to predefined synthetic datasets
- Uploads, storage, balance, and community posting features are disabled for demo users

---

## Setup

### 1. Environment Variables

Add the following to your `.env`:

```env
DEMO_MODE_ENABLED=true
DEMO_CODE_LENGTH=12
DEMO_SESSION_TTL_MINUTES=120

# Bootstrap the first admin account on startup (run once, then you can clear these)
ADMIN_BOOTSTRAP_EMAIL=admin@example.com
ADMIN_BOOTSTRAP_PASSWORD=your-strong-password
```

### 2. Run Migrations

The new `demo_codes`, `demo_sessions` tables and `is_admin`/`is_active` columns on `users` are created automatically by `schemas.sql` on startup — no manual SQL required.

### 3. Bootstrap Admin

On first startup with `ADMIN_BOOTSTRAP_EMAIL` and `ADMIN_BOOTSTRAP_PASSWORD` set, CASSIE will create an admin account if none exists. After that you can clear those env vars.

## Admin Workflow

### Log In as Admin

Navigate to `/login` and use your admin credentials. Normal login works for admins even in demo mode.

### Generate Demo Codes

```http
POST /api/admin/demo-codes/generate
Authorization: Bearer <admin-token>
Content-Type: application/json

{
  "count": 5,
  "expires_at": "2026-06-01T00:00:00Z"
}
```

Response includes plaintext codes **shown once only** — copy and distribute them:

```json
{
  "codes": ["AB3KPQR2STMN", "CD7XYZWVUTRE", "..."]
}
```

### List Existing Codes

```http
GET /api/admin/demo-codes
Authorization: Bearer <admin-token>
```

Returns masked metadata (first 4 chars + `****`), creation time, expiry, and usage status. `code_hash` is never returned.

### Deactivate a Code

```http
POST /api/admin/demo-codes/{code_id}/deactivate
Authorization: Bearer <admin-token>
```

### Manage Users

| Endpoint | Description |
|---|---|
| `GET /api/admin/users` | List all user accounts |
| `POST /api/admin/users/{id}/make-admin` | Grant admin privileges |
| `POST /api/admin/users/{id}/remove-admin` | Revoke admin privileges |
| `POST /api/admin/users/{id}/deactivate` | Deactivate a user account |

## Demo User Workflow

1. Navigate to `/demo-login` (or click **Use Demo Code** in the navigation menu)
2. Enter the 12-character code provided by an admin
3. A time-limited session starts — the yellow demo banner appears at the top
4. Use the platform normally within the restrictions below

### What Demo Users Can Do

- Browse and run jobs using predefined synthetic datasets
- View pipelines, community page, and forum threads
- Use the pipeline builder (without saving)

### What Demo Users Cannot Do

- Upload files or access Storage
- View or manage their balance
- Create forum threads
- Access `/register`, `/storage`, `/balance`

## Mock Datasets

Predefined datasets are defined in `mock/data/manifest.json`. The file ships with two synthetic datasets:

| ID | Description |
|---|---|
| `demo_ecoli_small` | Synthetic Illumina paired-end reads for E. coli K-12 (48 MB) |
| `demo_hifi_small` | Synthetic PacBio HiFi reads for a small test genome (120 MB) |

To add datasets, append entries to `manifest.json` following the existing schema and place the actual files under `DEMO_DATA_ROOT` (default: `mock/data/`).

---

## Security Notes

- Demo codes are **bcrypt-hashed** in the database — plaintext is never stored
- Each code can be used **once only** (atomic `used_at IS NULL` guard)
- Demo JWTs are stateless (`token_type: "demo_session"`, `is_demo: true`) — no DB lookup per request
- All restrictions are enforced server-side; frontend guards are UI-only
- Generic error messages are returned for invalid/expired/used codes (no enumeration)
- `GET /api/config/public` exposes only `demo_mode_enabled` and `demo_code_length` — no secrets

---

## Turning Demo Mode Off

Set `DEMO_MODE_ENABLED=false` (or remove it) and restart. All login, registration, and route behavior returns to normal. Existing `demo_codes` and `demo_sessions` rows remain in the DB but are unreachable.
